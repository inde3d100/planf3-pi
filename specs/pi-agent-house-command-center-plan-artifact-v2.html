Purpose

Adopt Planf3 as a meta-skill and use it to design a Pi-native Plan Artifact v2 workflow that coordinates serious work across Agent House, Command Center, Obsidian, git, and goal/evidence tools.

Problem

Our current workflows are strong but distributed: planning lives in skill output, goals live in the goal pipeline, evidence lives in tool calls, Agent House handoffs live in result folders, and Command Center board state lives separately. This creates drift during multi-room work.

Solution

Create Plan Artifact v2: a living plan artifact generated by a Pi-local Planf3-derived meta-skill. Markdown/Obsidian becomes canonical, optional HTML provides human review, and status/evidence hooks keep Agent House and Command Center synchronized.

Questionables

Should Plan Artifact v2 replace writing-plans?

No. Keep writing-plans as the current default and use Plan Artifact v2 opt-in for serious/multi-room work until evidence proves it is better.

Should Agent House auto-start next rooms from a plan?

No. Preserve manual handoff policy. The plan should improve handoff quality, not remove user control.

Should HTML be canonical?

No for our Pi lab. HTML is useful for review/export. Markdown/Obsidian should be canonical because it composes with our memory, git diffs, and source notes.

Notes

Non-goal

Do not globally install or replace existing skills in the bootstrap step.

Adoption principle

Planf3 contributes the lifecycle: create, update, build, reference maintenance, validation. Pi contributes goals, evidence, Obsidian, Agent House, and Command Center.

First proof

The first real proof should be a low-risk Agent House task where the plan artifact is passed through Intelligence → Build Studio → Quality Gate.
